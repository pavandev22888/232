## Confirmed path contract

For stable DWORD observations at ECX offsets `+0x08`, `+0x0C`, and `+0x10`, the no-growth branch is taken exactly when unsigned 32-bit `field_08 > field_10 + 1` (the `inc ecx` wraps as a DWORD). The modeled continuation requires the indexed pointer-table entry to be non-null. The helper computes `mask = field_08 - 1`, `masked = field_0c & mask`, writes `masked` back to `+0x0C`, selects `field_08` when `masked == 0` else `masked`, decrements, then ANDs with `mask`. That final index is used to load `[field_04 + index*4]`; after initialization it is stored to `+0x0C`, and `+0x10` is incremented. The return load recomputes `(field_08 - 1) & index`, equal to the selected index because the index was AND-masked.

For a non-null, 16-byte-aligned slot with at least `0xBC` accessible bytes, the helper clears byte ranges in the exact instruction order and copies the 16-byte constant at VA `0x4205AFD0` (`00 00 00 00 00 00 00 00 FF FF FF FF FF FF FF FF`) to slot `+0xAC`. The constant is source-backed, not inferred. The caller stores resolver EAX in EBX at `0x413F70F8`, calls opaque `0x41B70930` at `0x413F70FD`, loads the source pointer from `[ebp-0x28]` at `0x413F7102`, then issues the W6 stores through EBX. This is the concrete consumer sequence; whether the provider preserves EBX or has relevant side effects is not established, so continuity across that call is conditional. The new adapter accepts a resolved slot view plus the source bytes and optional local DWORD as explicit post-call observations, reusing `copy_history_store_prefix`; a missing DWORD observation is returned as unresolved without writing. It does not invoke or model `0x41B70930`.

`HistorySlotArrayView` labels DWORDs by observed offsets and represents the 32-bit pointer table as independent host-side byte views; it is not a recovered C++ object or ABI layout. `MOVAPS [eax+0x30]` and other aligned stores establish the 16-byte alignment precondition for this modeled branch. View size/alignment and array bounds are offline safety checks, not original checks. The model reports growth/helper or null-slot/allocator paths as unresolved. For a null entry it records the source-confirmed intermediate `+0x0C` masked store before returning unresolved; it does not call `0x413F3890` or `0x41DA7BAC`. It makes no claims about allocator behavior, slot ownership/lifetime, field meanings, target identity, provider side effects, or full history selection.
