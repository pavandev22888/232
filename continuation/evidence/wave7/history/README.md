## Confirmed path contract

For stable DWORD observations at ECX offsets `+0x08`, `+0x0C`, and `+0x10`, the no-growth branch is taken exactly when unsigned 32-bit `field_08 > field_10 + 1` (the `inc ecx` wraps as a DWORD). The modeled continuation requires the indexed pointer-table entry to be non-null. The helper computes `mask = field_08 - 1`, `masked = field_0c & mask`, and first writes `masked` to `+0x0C`. It selects `field_08` when `masked == 0` else `masked`, decrements EDI to form the cursor, then ANDs that cursor into EBX to form the distinct table index. At `0x413F899A`, the unmasked EDI cursor—not EBX—is written to `+0x0C`; `+0x10` is incremented. The return load recomputes `(field_08 - 1) & EDI` as the selected table index. For capacity 5, mask 4, and old cursor 4, final EDI is 3 while EBX is `3 & 4 == 0`; the final stored cursor is 3. No power-of-two capacity assumption is made. The previous model incorrectly stored the masked index and is corrected in this follow-up; see `coordinator-finding.md`.

For a non-null, 16-byte-aligned slot with at least `0xBC` accessible bytes, the helper clears byte ranges in the exact instruction order and copies the 16-byte constant at VA `0x4205AFD0` (`00 00 00 00 00 00 00 00 FF FF FF FF FF FF FF FF`) to slot `+0xAC`. The constant is source-backed, not inferred. The caller stores resolver EAX in EBX at `0x413F70F8`, calls opaque `0x41B70930` at `0x413F70FD`, loads the source pointer from `[ebp-0x28]` at `0x413F7102`, then issues the W6 stores through EBX. Whether the provider preserves EBX or has relevant side effects is not established. Accordingly the offline consumer requires a separately supplied `HistoryPostCallSlotObservation` after that opaque call; it does not automatically reuse the earlier `HistorySlotResolution` or claim the original caller re-resolves the pointer. Missing slot or DWORD observations are returned without writing. The adapter reuses `copy_history_store_prefix` and does not invoke or model `0x41B70930`.

`HistorySlotArrayView` labels DWORDs by observed offsets and represents the 32-bit pointer table as independent host-side byte views; it is not a recovered C++ object or ABI layout. For safe initialization, the offline adapter requires stable, pairwise non-aliasing storage for the view descriptor, entries descriptor array, and selected record. The modeled `+0x0C/+0x10` fields are intentionally updated. This is an explicit model precondition, not a recovered original aliasing guarantee. `MOVAPS [eax+0x30]` and other aligned stores establish the 16-byte alignment precondition for this modeled branch. View size/alignment and array bounds are offline safety checks, not original checks. The model reports growth/helper or null-slot/allocator paths as unresolved. For a null entry it records the source-confirmed intermediate `+0x0C` masked store before returning unresolved; it does not call `0x413F3890` or `0x41DA7BAC`. It makes no claims about allocator behavior, slot ownership/lifetime, field meanings, target identity, provider side effects, or full history selection.
