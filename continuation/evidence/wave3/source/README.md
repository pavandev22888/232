# W3-S — ограниченный источник N+14

**Результат:** одна гипотеза подтверждена на уровне локального писателя:
`0x414F840B` копирует в DWORD `N+14` четыре байта из `P+0`, где 32-битный
`P` прочитан из `0x4223CA04`. Это новая проверка alias/guard-цепочки по уже
сохранённым байтам V10, не заявление об обнаружении новых байтов или полном
происхождении часов. C++ и общие документы не изменены.

## Что установлено

- Reader `0x4150BE40` записывает `manager + index * 0x74` в выходной указатель.
  Enrichment передаёт адрес своего локального указателя, затем в `0x414F83C2`
  загружает его в EDI. Пример caller `0x414F69D5..69E9` передаёт менеджер из
  `0x424F46C0`. В локальном блоке запись идёт именно через этот EDI, а не через
  совпавшее смещение постороннего объекта, **при предпосылках вызовов ниже**.
- При входе в `0x414F83F2` обнуляется отдельное поле `+10`. Затем
  `UCOMISS(+0, N+14) / JNE` пропускает запись при ordered nonzero старом значении.
  `+0`, `-0` и unordered пропускают управление к загрузке `P`, чтению `P+0`
  и `MOVSS [EDI+14], XMM0`. Проверка byte активности N+00 идёт **после** записи;
  reader AL/BL не является её локальным gate. Полный входной guard не восстановлен:
  видны вход через ненулевой AL виртуального `+24` и обратный переход при нулевом
  AL `0x41B6FF10`, без назначения этим поставщикам выдуманной семантики.
- `0x414F85A7` сбрасывает DWORD `N+14`. Соседний `MOVSX WORD` записывает DWORD
  **N+1C**, а не `+14`. Сохранённые metadata hashes — архивный контекст,
  не доказательство внешнего типа `+14`. Инициализатор обнуляет `+14` внутри 16-байтных записей `N+0C..1B`
  обеих записей пары; шаг пары `E8`, записи `74`, всего 2048. Обнуление не
  доказывает первый положительный источник.
- Выбранный network-update записывает часы в **N+0C** (`0x4150B61B/1E → B671`).
  Его `[EBP+14]` — стековый аргумент. Это различение конкретных операндов,
  **не** доказательство отсутствия других писателей N+14.
- В consumer `0x414FD835` загружает результат того же reader в EBP;
  `0x414FDADF` читает DWORD `[EBP+14]` после чтения `P+0` через тот же адрес
  глобального указателя. Пример caller из `0x4150536E` передаёт тот же
  статический manager slot. Это связывает семейство/раскладку записей,
  но не доказывает равенство двух runtime-экземпляров или наблюдений часов.

## Предпосылки и точный frontier

Обычный возврат вызовов с сохранением nonvolatile EDI/ESI/EBP и стека,
отсутствие скрытой порчи локального указателя/записи — **предпосылки**, не
проверенная реализация виртуальных/TLS-поставщиков. Локальные окна не закрывают
opaque/перекрывающийся вход и весь CFG. Для UCOMISS рассматриваются quiet NaN
при отключённых FP traps; не доказываются sNaN, MXCSR/FTZ/DAZ.

`EDI_N(t_write) == EBP_N(t_read)` требует одинаковых значений manager и индекса
в двух вызовах. Статический адрес `0x424F46C0` и шаг `74` этого не доказывают.
Так же два чтения `0x4223CA04` не гарантируют одинаковый `P` или `P+0`.
**Следующая неизвестная граница — поставщик/время жизни P и писатель P+0**;
их происхождение и полная семантика здесь не установлены. Сохраняются неизвестные
прочие writers/aliases, конкурентные изменения и достижимость. Записанное
значение не обязано быть положительным, ненулевым или конечным. `now` остаётся
названием уже существующей модели, а не доказанным внешним типом.

## Повторение

Из корня worktree:

```sh
python3 continuation/evidence/wave3/source/verify_source.py \
  --handoff /tmp/hoplite/workspace/runs/handoff/RAGEBOT_HANDOFF_V10
```

Нужны Python 3 (stdlib) и GNU objdump. `--handoff` обязателен и только читается;
скрипт вообще не пишет файлов и не импортирует модули handoff. `ledger.json`
фиксирует SHA-256 образа (55 578 624 байта), восьми контекстных JSON и 12 окон.
Свежий GNU objdump проверяет **257 инструкций / 1039 байт**, полное покрытие окон,
совпадение с архивными инструкциями и якоря шести ограниченных утверждений.
Интерпретация цепочки — ручной статический аргумент, не формальная проверка
полной программы. Ни исходный модуль, ни legacy scripts не запускались,
не загружались и не эмулировались. Target aggregation/threshold не исследовались;
прочие прежние кандидаты не пересматривались. Никакой C++-заглушки не добавлено.
