# Адресно-исходная карта и пределы доказательства

Образ: `workspace/work/nl_handoff_2026-11-06/nl.bin` восстановленного комплекта.
Условная база для адресной нотации: `412A0000`; это не утверждение о рабочей базе.
Хеш образа, точные инструкции и пять float-констант — `byte_anchors.json`.
`verify_evidence.py` сверяет их с исходным файлом и заново декодирует GNU objdump.

## Уровни уверенности

1. **Байты и локальная цепочка:** инструкции, регистры, ширина чтения/записи,
   шаг N, непосредственные условия и константы.
2. **Условная реконструкция:** C++ сохраняет эти операции при перечисленных
   предпосылках; тесты подтверждают поведение именно этого кода на своих входах.
3. **Гипотеза:** назначения непрозрачных полей намеренно не домысливаются.
4. **Неизвестно:** полная достижимость, охранные ветви, внешние провайдеры и
   эквивалентность работающему оригиналу. Байтовый тест это не закрывает.

Все реализации находятся в `src/position_records.cpp`, раскладка и API —
`include/rage/position_records.hpp`, тесты — `tests/test_position_records.cpp`.

## 1. `PositionStore::PositionStore` / `PositionRecord`

Источник `v10/position_manager_initializer_walk.json`, сегмент `initialization`.
`412C2F21..412C2F38`: выделение и обнуление `3A000` байт. Цикл
`412C2F50..412C2FDF` обрабатывает пары с шагом `E8`, пишет `100` в `N+8`.
`3A000 / 74 = 2048`. Сохранение базы менеджера: `412C2FE5`.

Офлайн-вариант владеет `std::array` и не воспроизводит исходный allocator,
деструктор, регистрацию завершения или поведение при ошибке выделения.
Неизвестные байты не получают выдуманных смыслов. Поля проверяются `static_assert`.
Тест: `initialization`.

## 2. `update_resolved_record`

Источник `v10/network_update_with_tls_tails_walk.json`.
Предпосылки: нужная запись уже выбрана; предыдущие внешние проверки и охраны
пройдены; вызов трассировки и нужные TLS-инициализаторы успешно вернулись.
Функция **не моделирует** побочные эффекты этих вызовов или их ошибки.
В исходном указателе N: база в EBX, индекс умножен на `74` в ECX по `4150B3AF`;
смещение сохраняется в scratch `+BC` по `4150B3DE` и восстанавливается в EDI
по `4150B589`. Это **не** прежний неизвестный положительный источник `+BC`.

- `4150B3B2..4150B3C6`: UCOMISS/JNE; совпадение **или unordered** допускает
  запрет по большему знаковому типу N+20.
- `4150B3CC..4150B3D8`: только тип 2, сравнение N+58 с входной меткой через **JG**.
- `4150B556..4150B584`: all-solid, start-solid, затем fraction=1 **или NaN** — отказ.
- `4150B59E..4150B619`: включение активности; сравнение текущей позиции N+24 с
  снимком N+3C через UCOMISS/JNE; порядок переноса меток N+60/+64 и типа N+68;
  снимок берёт **старую**, а не входную позицию. При равных метках нужен больший тип.
- `4150B621..4150B637`: метки N+58/+5C обновляются и без замены снимка.
- `4150B63F..4150B671`: граница `now + interval * (-256)`; JAE сохраняет старый
  N+18, иначе записывается `now - old_time`; затем обновляется N+0C.
- `4150B675..4150B6BE`: SETB относительно float `0.97` и `(type & ~4) != 1`.
  Типы 1 и 5 оставляют входную позицию; точное равенство `0.97f` тоже оставляет её.
- `4150B6C4..4150B6DF`: TLS-граница **не закрыта**, в коде предполагается её
  успешное прохождение; не утверждается, что частичные записи при ошибках исключены.
- `4150B6E5..4150B741`: маска на основе сравнений с 1 и 0.5 и внешних флагов.
  Назначение отдельных битов не выдумывается.
- `4150B745..4150B777`: тип, tick, затем tag только при неотрицательном входе.

Часы/interval/tick считаются стабильными между повторными чтениями внутри вызова.
Состояние однопоточное, аргументы не алиасят запись. Float — IEEE binary32,
округление nearest-even, без fast-math/FMA, ловушки FP выключены, FTZ/DAZ выключены.
Quiet NaN поддержан; исключения signaling NaN, флаги FPU и произвольная среда
округления не воспроизводятся. Возвращаемый `UpdateEffect` — диагностика нашего
API, не значение AL исходной функции. Предел 64 и нулевой/локальный индекс
проверяются **до** нашего входа, не являются реализованным полным packet gate.
Тесты: `update_lifecycle`, `rejected_updates_do_not_write`, `snapshot_rules`,
`numerical_boundaries`.

## 3. `store_resolved_item_definition`

Источник `v10/record_actor_enrichment_walk.json`.
`414F83BD` вызывает тот же читатель, `414F83C2` загружает выданный N в EDI.
`414F8552..414F856E` читает и разрешает handle; при нулевом результате прыжок
сразу на `414F85A7`, минуя store. При успешном стабильном разрешении
`414F859B..414F85A4`: MOVSX WORD → DWORD N+1C. Ноль WORD — настоящий ноль,
а отсутствующий объект сохраняет прежнее поле.

Хеши m_hActiveWeapon/DT_BaseCombatCharacter и
m_iItemDefinitionIndex/DT_BaseAttributableItem подтверждены повтором V10;
здесь используются разрешённые данные, а не фальшивый resolver или адрес модуля.
API не воспроизводит прочие записи/ветви функции `414F8330`.
Тест: `metadata_and_connected_chain`.

## 4. `read_resolved_record`

Источник `v10/position_record_reader_walk.json`.
Новая детализация относительно конечного предиката модели V10:

1. `4150BE8F..4150BEAD`: индекс поставляется виртуальным методом; допустимая
   область `<2048`, шаг `74`; **выходной указатель записывается до проверки источника**.
2. `4150BEAF..4150BEC7`: нулевой результат `41B6C670` — отказ без изменения N;
   индекс `>64` идёт прямо к активности/давности.
3. Для индекса `<=64`: `4150C19F..4150C1A9` читает внешний байтовый флаг;
   если он ноль, идём к настройке. Иначе `4150C47F..4150C48B` читает знаковый
   DWORD: положительный обходит настройку, неположительный — нет.
4. `4150C48D..4150C4A8`: byte cfg+366 равен нулю — выбирается cfg+364,
   любой ненулевой — cfg+365. Это следует из CMP/SBB, не из предполагаемого UI.
5. `4150C4AA..4150C4B8`: выбранный byte=0 **или** N+48 равен нулю/**NaN** →
   active=0. Иначе сохраняется активность. Здесь маркер не обязан быть положительным:
   отрицательный конечный float проходит локальное JNE.
6. `4150C4BA..4150C4DD`: ненулевой **byte** активности и SETB для `now - N+0C`
   относительно 4. Ровно 4 отклоняется; отрицательный возраст и unordered проходят.
   Упавшее чтение источника/сброс активности/неактивность предшествуют этой проверке.

Вычисление смещений внешних таблиц, TLS и вызываемые функции не реализованы;
`ResolvedRead` принимает их результаты. При индексе >=2048 оригинал переходит
к неизвестному обработчику `412AF300`; наш `outside_supported_domain` — отдельный
защитный контракт, **не реконструкция его результата**. Заимствованный указатель
остаётся доступен при обычных отказах, но не служит доказательством пригодности.
Тесты: `reader_policy`, `reader_boundaries_and_borrowing`.

## 5. `passes_item_consumer_gate`

Источник `v10/position_reader_caller_anchor_walk.json`, `413650D2..413650F7`:
тот же менеджер → читатель → проверка AL → проверка N+1C != 0. Только эта
входная развилка восстановлена, дальнейшая обработка не объявлена реализованной.
Тест связывает обновление, запись метаданных, чтение и отказ по возрасту.

## Что доказательство не делает

Выбранные интервалы не объявлены полными функциями. Пропущенные внешние ветви
не названы мёртвыми; все исходные обходы сохранены. N+48 пока является входным
маркером с неизвестной полной семантикой/источником, а не заглушкой,
возвращающей удобную константу. Никаких выводов о реальном серверном исходе,
живой ошибке игры или независимом аудите из тестов не следует.
