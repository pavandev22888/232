# GAP01 — первые положительные источники

**Итог: все три источника остаются открытыми.** Уточнены условия и типы двух сильных совпадений по смещению; ни одно не доказывает запись в нужную запись Point/T. Статически подтверждённый перенос `Point+26 → T+96` — это распространение уже существующего значения, а не его происхождение.

## Выводы

- **Point+26.** Кандидат `0x4149BB92` действительно декодируется как четырёхбайтовый `ADD [EAX+0x25],0x6A`, перекрывающий байт `+26`. Перед ним `EAX` загружается из `G424B004C`; запись пропускается при `EBX < 65`. Далее тот же глобальный корень используется как база таблицы с шагом `0x10940`. Ни равный байтовый диапазон, ни эта табличная ссылка не доказывают, что адрес является Point. Кандидат не принят как setter Point. Выделитель Point отдельно обнуляет блок `+20..+2F` и ставит sentinel в `+2C`; это только инициализация.
- **T+F4.** Конструктор T получает `this` в `EDI`; запись `MOVUPS [EDI+0xEC],XMM0` обнуляет область, включающую `+F4`. Найденный положительный литерал в `0x4147F648` пишет в `ESI+F4`, но в этой функции `ESI=ESP` после выделения стекового кадра `0x510` — это не T. Литерал переносится в локальное `+3C`, затем `+F4` очищается. Отдельно сканер пишет `T+F0`, не `T+F4`. Селектор сравнивает DWORD `+F4` двух записей и переходит на отказ при неравенстве; первичный setter и смысл значения неизвестны.
- **Старый G425009BC (+BC).** В известном ограниченном census два прямых писателя — байтовые сбросы в `0x41595497` и `0x415DECEE`. Потребители используют флаг в локальных ветвлениях, например `OR` с `G425009E9` в stop helper или сравнение с нулём перед вызовом в target coordinator. Положительный setter не найден; ограниченный census не доказывает его отсутствия через вычисляемый адрес/alias.

Никакой ветви не объявлено мёртвой: guards сохранены буквально, а неисполнение конкретной ветви не выводится из условного графа. Все байты проверяются относительно `nl.bin` с SHA-256 `682ce73b371349f87da6fd9365f8550e240dcdb97951e80445e70286275ad96e` и условной базой `0x412A0000`.

## Воспроизведение

```sh
python3 continuation/evidence/gap01/verify_gap01.py
```

Проверка только читает комплект: сверяет хеш, соответствие выбранных строк сохранённым обходам, байты по `VA - 0x412A0000` и свежие декодирования GNU objdump. Она не доказывает достижимость, полноту поиска, живое состояние или эквивалентность DLL. `candidate_ledger.json` содержит разбор каждого поля и остаток доказательства.

## Остаточная граница

Для закрытия GAP01 нужен новый типизированный alias/source path для `Point+26`, положительный setter нужного экземпляра T для `T+F4`, и положительный setter/alias для `G425009BC`, каждый с условием и downstream-потребителем. В доступных материалах эти три цепочки не замкнуты; новые C++-тела не добавлялись, чтобы не кодировать догадку.
