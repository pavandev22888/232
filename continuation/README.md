# Продолжение V10: типизированная позиционная цепочка

**Добавлен работающий офлайн-C++-код локального участка, не полный Ragebot.**
Новые файлы находятся в `continuation/` корня репозитория. Восстановленный комплект
сохранён отдельно: `runs/handoff/RAGEBOT_HANDOFF_V10/`; его собственная папка
`continuation/` и все архивные материалы оставлены неизменными.

## Что реализовано

- Запись **N** размером `0x74` с проверяемой раскладкой и владеющее хранилище
  из 2048 записей. Исходная инициализация: нули и начальное значение `tag = 100`.
- Обновление после внешних проверок: приоритет типа при совпадающей временной
  отметке, знаковое сравнение меток для типа 2, отказы геометрической проверки,
  перенос старой позиции и меток, расчёт интервала, выбор входных/скорректированных
  координат, маска флагов и условная запись дополнительного значения.
- Читатель с уже разрешёнными внешними значениями: выдача записи даже при отказе,
  обход настройки для определённых индексов/значений таблиц, сброс активности
  по настройке и маркеру `+48`, затем активность и строгое сравнение давности с 4.
- Знаковое расширение разрешённого 16-битного идентификатора предмета в `+1C`.
  Отсутствие разрешённого объекта **не обнуляет** прежнее значение.
- Два условия входа в найденный потребитель: успешное чтение и ненулевой
  идентификатор. Отрицательный идентификатор тоже проходит это локальное условие.

Это реальные тела функций с типами и состоянием, а не исполняемые заглушки.
Неизвестные поставщики вообще не реализованы: их результаты передаются явно.

## Воспроизведение

Нужны Python 3.10+, GNU objdump, make и C++17-компилятор с ASan/UBSan.
Сборка не требует Windows, IDA, Ghidra, CMake или загрузки DLL.

```sh
make -C continuation check
# Для другого расположения уже восстановленного комплекта:
make -C continuation check HANDOFF=/absolute/path/RAGEBOT_HANDOFF_V10
```

`test` запускает функциональные тесты; `sanitize` — те же тесты с ASan/UBSan;
`evidence` повторно проверяет хеш образа, байты, декодирование инструкций и
неизменность инвентаризированных исходников. Артефакты сборки пишутся в `build/`.
Не включайте `-ffast-math`: он разрушает существенные свойства сравнений с NaN.

## Как читать результат

- [`PLAN.md`](PLAN.md) — инвентаризация и план дописывания, а не обзор заново.
- [`evidence/SOURCE_MAP.md`](evidence/SOURCE_MAP.md) — адреса, цепочки, предпосылки.
- [`evidence/byte_anchors.json`](evidence/byte_anchors.json) — исходные байты и константы.
- [`evidence/baseline_checks.json`](evidence/baseline_checks.json) — новый прогон V10–V6.
- [`STATUS.json`](STATUS.json) — выполненное и открытые задачи.
- [`DECISIONS.md`](DECISIONS.md) — решения и ограничения.

### Не является завершённой реконструкцией

Не восстановлены полная доставка/формат пакетов, геометрический провайдер,
разрешение игровых объектов, TLS/охранные ветви, весь источник маркера `+48`,
остальной потребитель и полный жизненный цикл метаданных. **N+68 — тип снимка,
а не порог T+68.** Три старых положительных источника и потребитель T+68 этим
участком не закрыты. Таблица на 2048 записей не означает 2048 игроков.

Тесты используют синтетические состояния и собственный код. Сверка байтов
подтверждает инструкции, но не достижимость всего пути в игре и не независимый
аудит эквивалентности. Исходные DLL не запускались, не загружались и не эмулировались.
