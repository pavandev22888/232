# Дорожная карта к полному читаемому C

Цель и строгие критерии: [GOAL.md](GOAL.md). Реестр назначений, зависимостей,
областей записи и критериев каждой карточки: [TASKS.json](TASKS.json).
Он является источником статусов следующей работы; текущие полные GAP-статусы
остаются в [continuation/STATUS.json](../continuation/STATUS.json).

## Отправная точка

W3–W4 завершены и приняты в ограниченной области; не запускайте их заново
как невыполненный план. Есть шесть C++17-модулей и статические свидетельства,
а не полный алгоритм. Перенос на C ещё не начат. Результат подготовки этого
handoff — документация и воспроизводимость, не закрытие CODE01/GAP01–GAP06.

## Последовательность ограниченных волн

| Этап | Задания | Выход и условие перехода |
|---|---|---|
| 0. Вход | BOOTSTRAP + baseline | Архив собран, input/work проверены, текущий `make check` выполнен; зафиксирован SHA |
| 1. Первый код на C и карта полноты | C01 + R01, независимо | Один принятый C17 scalar-helper с тестами; карта всех областей цели и доказательств/unknowns |
| 2. Перенос состояния | C02 + C03 после C01 | C17 storage/update/reader и charge; явное владение, статусы, layout; старые тесты не ослаблены |
| 3. Связки на C | C04 после C01/C02 | Lifecycle, optional output, marker/actor compositions в пределах нынешних контрактов |
| 4. Закрытие доказательных разрывов | R02/R03/R05; R04 только при новом основании | По одному типизированному источнику, provider или переходу, с точным frontier при неуспехе |
| 5. Интеграция и воспроизводимость | I01 + V01 | Связная C17-библиотека доказанных участков; независимый review SHA; оставшиеся исторические gates не скрыты |
| 6. Полный контур | FULL01 и новые задачи из R01 | Все необходимые области и зависимости восстановлены, критичных unknowns нет, критерии полноты действительно выполнены |

Этапы 4 и проверочная работа V01 могут идти параллельно C-порту, если write paths
не пересекаются. Это не обещание закончить все этапы за одно назначение и не
основание продолжать бесконечный поиск. После каждой волны — commit, проверка,
обновлённый остаток и остановка на согласованном ограниченном результате.

## Рекомендуемое следующее назначение

**C01**: перенести уже доказанный scalar helper в C17 и сохранить его точную
float-семантику. Это даёт настоящий код на требуемом языке без выдумывания
неизвестных providers. Параллельно **R01** строит карту транзитивного контура,
чтобы перенос helpers не подменил цель полного Ragebot.

Затем координатор выбирает небольшой доказуемый участок по результатам R01.
Для CODE01/T+68 сначала нужен установленный тип/поток/ветвь; inventory не является
готовой реализацией или разрешением обходить ограничения прежних назначений.
Не пытайтесь закрыть full-task одним helper или количеством проверок.

## Что нельзя скрыть в плане

- Порт C++ → C не восстанавливает отсутствующий алгоритм и не закрывает GAP.
- Сетевой путь, выбор цели/точки, геометрия и прочие области полной цели
  должны иметь отдельные доказательные карточки после R01, а не фиктивный общий PASS.
- Для N+14/P/P+0 не начинается новое широкое исследование без конкретного
  дополнительного байтового основания; R04 остаётся blocked.
- 12 исторических H01-пунктов, наблюдаемая эквивалентность и внешний аудит
  остаются отдельными обязательствами; нынешние агентные проверки их не заменяют.
- Если имеющихся материалов недостаточно, описать точную недостающую связь и
  продолжить другую ready-задачу. Не требовать заново все исходники как условие
  любого прогресса: исходный комплект уже в репозитории.
- FULL01 — критерий окончания проекта, **не задача на один запуск**. Все карточки
  могут уточняться по новым данным без снижения критериев и переписывания истории.

Публикация каждой принятой волны — в существующую рабочую ветку/PR, без слияния,
очереди и auto-merge до нового указания пользователя.
