# Промпты для передачи работы

Для исполнителя и рецензента замените поля в угловых скобках. Сначала дайте агенту доступ к репозиторию и
ветке, затем текст задания. Если модель не читает `AGENTS.md` автоматически,
прямо приложите его содержание. История чата не нужна.

## Координатор / новый основной агент

Для продолжения всего остатка используйте [готовый промпт](START_NEXT_AGENT.md)
целиком, без заполнителей. [HANDOFF](HANDOFF.md) содержит все принятые/открытые
области, blockers, H01 и первый рабочий участок. Не ждать `ready`-карточку:
на снимке W5 таких нет; новый координатор после сверки владельцев создаёт
ограниченные назначения для следующей волны.

## Исполнитель ограниченной задачи

```text
Task ID: <ID>
Worktree: <absolute path>
Branch: <branch>
Base SHA: <full SHA>
Write paths: <exclusive list>
Goal/contract: <bounded result from task card>
Read first: <specific source, contract and evidence paths>
Acceptance: <commands + expected scope, not a fake expected PASS>
Stop condition: <accepted bounded result or exact unresolved frontier>

Прочитай AGENTS.md и docs/AGENT_WORKFLOW.md. Работай только в назначенном
worktree и write paths. Handoff: <absolute read-only path>.
Не меняй общие status/Makefile/планы, не push/merge и не трогай чужие файлы.
Не запускай/не загружай/не эмулируй оригинальные DLL, не подключайся к игре.
Привяжи утверждения к байтам и предпосылкам; не подменяй неизвестные заглушками.
Проверь diff и узкие тесты, закоммить свои файлы и верни результат по шаблону
docs/AGENT_WORKFLOW.md: SHA, команды/exit codes, evidence, ограничения.
```

## Рецензент

```text
Проверь результат <TASK_ID> на фиксированном интегрированном SHA <SHA>.
Отдельный review-worktree: <path>; handoff: <absolute read-only path>.
Scope и разрешённые отчёты: <paths>. Код не исправляй; findings верни координатору.

Прочитай AGENTS.md, карточку задачи, исходные контракты и diff относительно <base>.
Отдельно проверь байтовые основания, типы/идентичность объектов, неизвестные
providers/ветви, порядок операций, NaN/±0/aliasing, тесты и воспроизводимость.
Повтори назначенные проверки; для полного acceptance нужен make check.
Проверь, что язык/ABI оригинала опираются на источники, а не на расширение
декомпилята или язык текущего harness. Принудительный C17-порт не требуется.
Синтетические тесты не называй эквивалентностью оригиналу или внешним аудитом.
Применяй тот же офлайн-режим без загрузки/исполнения/эмуляции оригинальных DLL.

Верни blocking findings с file:line и конкретным основанием, реально выполненные
команды/exit codes, непроверенное и вердикт только в пределах scope.
Отсутствие найденной ошибки не закрывает неизвестные GAP или весь Ragebot.
```
